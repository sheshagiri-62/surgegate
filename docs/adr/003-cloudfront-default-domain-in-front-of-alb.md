# ADR 003 — CloudFront default domain in front of a Terraform-owned ALB (no custom domain yet)

- **Date:** 2026-11-20
- **Status:** Accepted
- **Related:** [ADR 001](001-eks-sqs-eventbridge-kinesis-static-buyer-site.md); implementation plan Day 2 Task 4 and M1

## Context

The plan's Day 2 Task 4 is: *"`edge` module (first part): Route 53 zone, ACM certificate, ALB ingress
for `api.<domain>`"*, and M1 is checked at `https://api.<domain>/healthz`. There is no domain yet: a
Route 53 domain registration failed. We still need a public **HTTPS** URL for the booking API now,
and the design must accept a real domain later without being rebuilt.

Constraints:

- The ALB must not be open to the whole internet. The blueprint puts CloudFront and WAF in front of
  everything ("only buyers holding a valid booking pass reach the VPC").
- No secrets in Git (CLAUDE.md safety rule 2).
- Everything hourly must disappear with `make down`.

## Decision

1. **CloudFront's default domain** (`dxxxx.cloudfront.net`) serves the API over HTTPS with
   CloudFront's own certificate. Route 53 zone, ACM certificate (us-east-1), the CloudFront alias and
   the DNS records are already in the `edge` module behind `var.domain_name`. Setting it later
   switches to `https://api.<domain>` with no other change.
2. **The ALB accepts traffic only from CloudFront**, enforced twice:
   - **Network:** the ALB security group allows port 80 only from the AWS-managed prefix list
     `com.amazonaws.global.cloudfront.origin-facing`.
   - **Application:** CloudFront adds a secret header `X-Origin-Verify` to every origin request. The
     ALB listener's default action is **403**, and only a rule matching that header forwards to the
     target group. The prefix list alone isn't enough, because any CloudFront distribution
     (including someone else's) uses those same IP ranges.
3. **The secret lives in Secrets Manager** (`surgegate/dev/edge/origin-verify`, generated by
   Terraform with `random_password`), never in Git. Terraform passes it to the CloudFront origin
   header and the ALB rule.
4. **Terraform owns the ALB, listener, rule and target group**, instead of a Kubernetes Ingress
   handled by the AWS Load Balancer Controller. The booking-api Helm chart only contains a
   **TargetGroupBinding** that finds the target group **by name**
   (`surgegate-dev-booking-api`) and registers the pod IPs.
5. **CloudFront → ALB uses HTTP** (`origin_protocol_policy = "http-only"`) for now. Viewers always
   get HTTPS (`redirect-to-https`).
6. ALB and CloudFront follow the `enable_eks` switch, so `make down` destroys them. The secret
   stays ($0.40/month) so its value is stable between sessions.

## Consequences

**Good**

- A real HTTPS URL today, at no domain cost. Moving to `api.<domain>` is a variable change.
- The ALB can't be used directly: wrong source IP → no TCP connection; right IP but no secret
  header → 403. This also stops anyone from bypassing a future WAF on CloudFront.
- No secret in Git. An Ingress would have needed the header value in an annotation, inside the
  chart.
- Because Terraform (not the controller) creates the ALB, `make down` reliably removes it. There's
  no orphaned ALB billing after the cluster is gone, which is a common EKS teardown failure.
- The target group name is fixed, so a recreated ALB needs no Git change. The TargetGroupBinding
  re-registers pods after every `make up`.

**Bad / trade-offs**

- **CloudFront → ALB is unencrypted HTTP.** The ALB can't get a certificate for its
  `*.elb.amazonaws.com` name, and there's no domain to issue one for. Viewer traffic is encrypted;
  the CloudFront → ALB hop isn't. That's acceptable for the dev hello-world API, **not** for real
  payment or personal data. With a domain, the next step is an ACM certificate in ap-south-1 on an
  HTTPS listener and `origin_protocol_policy = "https-only"`.
- The `*.cloudfront.net` name changes whenever the distribution is recreated (each `make up`), so
  the M1 URL is read from `terraform output api_url` each session, not bookmarked.
- `make down` / `make up` take a few minutes longer (CloudFront deploys and disables).
- The ALB and its rules aren't visible as a Kubernetes Ingress. To find "how traffic reaches the
  pod", read the `edge` module and the TargetGroupBinding together (documented here and in the
  chart).
- The secret value is stored in Terraform state (S3, encrypted, private) and in the CloudFront and
  ALB configuration, so the CI plan role gets `GetSecretValue` on `surgegate/*/edge/*` (it can
  already read the state).

## Alternatives considered

| Option | Why not (now) |
| --- | --- |
| Route 53 + ACM + `api.<domain>` (the plan as written) | No domain: registration failed. Kept behind `var.domain_name` |
| Ingress managed by the Load Balancer Controller, with a header condition annotation | The secret header value would sit in Git (chart annotation); the ALB would outlive `make down` unless every Ingress is deleted first |
| Public ALB DNS name only, no CloudFront | No HTTPS (no certificate for `*.elb.amazonaws.com`); ALB open to the internet |
| CloudFront **VPC origin** with an internal ALB | Removes the public ALB entirely, and it's the better long-term design. Not chosen today to follow the agreed approach and keep Task 4 small; worth revisiting in Phase 5 with WAF |
| Free dynamic-DNS / third-party domain | Adds an external dependency outside Terraform and AWS; a real domain is the cleaner fix |
